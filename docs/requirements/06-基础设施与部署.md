# 基础设施与部署模块详细需求

## 1. 模块目标

为前端、后端、AI 三个服务提供统一、可复制的运行环境：数据可靠存储、中间件一键编排、配置与密钥分离、三服务可独立开发与部署，并支撑压测与日常运维。

## 2. 服务拓扑

```text
浏览器
  └─ 前端 Vue3 (Vite :5173，/api 与 /uploads 代理到 :8080)
        ├─ 后端 Spring Boot (:8080)
        │     ├─ MySQL      :3306   业务数据
        │     ├─ Redis      :6379   验证码 / 缓存
        │     ├─ MinIO      :9000/9001  媒体对象存储
        │     ├─ Qdrant     :6333/6334  向量库
        │     └─ FFmpeg            视频处理（本地命令）
        └─ AI Agent FastAPI (:8000)
              ├─ DeepSeek API          LLM
              └─ 通义 DashScope        VL 视觉 / Embedding
```

## 3. 中间件需求

| 组件 | 版本/规格 | 用途 | 关键配置 |
| --- | --- | --- | --- |
| MySQL | 8.0+，库名 `dy`，utf8mb4 | 7 张业务表 | 初始化脚本 `sql/init.sql` |
| Redis | 7+ | 图形/邮箱验证码、缓存；开 AOF 持久化 | 端口 6379 |
| MinIO | latest | 视频/图片/头像/背景，bucket `dydemo` | S3 API 9000，控制台 9001 |
| Qdrant | latest | `video_embeddings`（1024 维 Cosine） | REST 6333 / gRPC 6334，API Key 鉴权 |
| FFmpeg | 系统 PATH 或配置完整路径 | 视频元数据/帧处理 | `ffmpeg.path` |

数据表：users、works、likes、follows、comments、watch_history、messages（见 `sql/init.sql`）。

## 4. 容器化编排（docker-compose.yml）

- 服务：`qdrant`、`minio`、`redis`、`agent-service`（build 自 `./agent-service`）；`mysql` 默认注释（使用宿主机 MySQL，需要时取消注释）。
- 均配置 `restart: unless-stopped`、健康检查（healthcheck）与数据卷持久化。
- agent-service 依赖 qdrant 健康后启动；通过 `SPRING_BOOT_API_URL=http://host.docker.internal:8080` 回调宿主后端。
- 常用命令：
  - `docker compose up -d qdrant minio redis`（仅中间件）
  - `docker compose up -d --build agent-service`（重建并启动 Agent，改代码后必做）

## 5. 配置管理

### 5.1 后端 `application.properties`（由 `.example` 复制）

- 文件上传：单文件 100MB；Tomcat/异步超时 120s（适配 SSE）。
- 数据源、Redis、QQ 邮箱 SMTP（587 + STARTTLS）、MyBatis-Plus 驼峰映射。
- JWT：密钥、access 30 分钟（1800000ms）、refresh 7 天（604800000ms）。
- DeepSeek（chat）、通义 VL（qwen-vl-plus）、Embedding（text-embedding-v3，1024 维，默认复用 VL key）。
- Qdrant、FFmpeg、Agent 地址、MinIO（endpoint/密钥/bucket/URL 前缀）。

### 5.2 Agent `agent-service/.env` / 环境变量

`DEEPSEEK_API_KEY`、`DEEPSEEK_API_URL`、`DEEPSEEK_MODEL`、`QDRANT_HOST/PORT/API_KEY/COLLECTION`、`EMBEDDING_API_KEY/URL/MODEL/DIM`、`SPRING_BOOT_API_URL`、`AGENT_PORT`。

### 5.3 配置规则

- 密钥只通过环境变量/本地配置注入，不写入代码；`application.properties`、`.env` 必须被 gitignore。
- 历史脚本中曾硬编码 API Key/数据库密码，需删除并轮换。

## 6. 本地启动流程

1. 启动中间件：`docker compose up -d qdrant minio redis`；MySQL 使用宿主机实例。
2. 初始化数据库：执行 `sql/init.sql` 创建 `dy` 库与表。
3. 后端：复制配置模板并填值 → `mvn spring-boot:run`（:8080）。
4. Agent（可选）：建虚拟环境装 `requirements.txt` → 配 `.env` → `uvicorn main:app --host 0.0.0.0 --port 8000`。
5. 前端：`npm install` → `npm run dev`（:5173）；构建用 `npm run build`。
6. 首次启用 AI 推荐：调用 `POST /api/vector/process-all` 全量向量化。

## 7. 工程与运行环境要求

- Node.js `^22.18.0 || >=24.12.0`；Java 17 + Maven；Python 3.12（Agent）。
- 后端 Maven Wrapper（mvnw）可免装 Maven；Agent 提供 Dockerfile（python:3.12-slim + uvicorn 启动）。

## 8. 可观测与运维需求

- Agent 关键行为打日志（工具调用、exclude_tags、检索条数、降级事件）；暴露 `/health`。
- 向量化为后台任务，提供进度/停止/单条重跑接口。
- 压测体系：`jmeter/` 提供列表接口、视频下载、混合浏览三套计划，阶梯加压脚本与结果汇总脚本。

## 9. 安全基线

- JWT 拦截器 + Spring Security 双放行白名单（公开内容、认证、验证码、作品、点赞等）。
- 业务错误返回非 200；Agent CORS 当前为 `*`，生产需收紧。
- Qdrant/MinIO 使用强密码与 API Key；生产不使用默认凭据。
