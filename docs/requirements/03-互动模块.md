# 互动模块详细需求

## 1. 模块目标

提供观众与作品之间的互动能力：点赞与评论。要求操作即时反馈、计数准确、未登录可浏览互动数据，写操作鉴权，并能支撑高并发场景。

## 2. 功能需求

### 2.1 点赞

- 在作品上点赞/取消点赞：**同一接口切换状态（toggle）**，返回当前是否已赞（Boolean）。
- 查询单作品当前用户是否已赞（未登录时返回未赞，接口整体放行）。
- 作品卡片与详情实时展示点赞数，点赞后图标动效与数字即时更新。
- "我的喜欢"：分页查看指定用户点赞过的作品。
- 作品表的点赞计数随点赞/取消同步增减。

### 2.2 评论

- 查看某作品的评论列表（含评论人头像、昵称、内容、时间），公开可看。
- 发表评论：必须登录；内容非空、长度受限；返回带作者信息的完整评论对象。
- 作品表评论计数随发表/删除同步。

### 2.3 未登录访问策略

- `/api/likes/**` 在 JWT 拦截器排除，未登录用户可正常看视频、看点赞数与评论。
- 未登录用户触发点赞/评论时，前端引导跳转登录页。

## 3. 业务规则

- 点赞关系唯一（同一用户对同一作品只有一条有效关系），toggle 幂等。
- 评论只能删除自己的（当前仅支持发表与查看，删除能力按需开放）。
- 互动写操作用登录 token 取 userId，不信任前端传入。
- 业务失败返回非 200 状态码，前端统一提示。

## 4. 接口清单

| 方法 | 路径 | 说明 | 鉴权 |
| --- | --- | --- | --- |
| POST | `/api/likes/{workId}` | 点赞/取消点赞（toggle），返回是否已赞 | 登录写；接口放行 |
| GET | `/api/likes/{workId}` | 当前用户是否已赞 | 放行 |
| GET | `/api/likes/list/{userId}?page&size` | 某用户点赞过的作品 | 放行 |
| GET | `/api/comments/{workId}` | 作品评论列表 | 放行 |
| POST | `/api/comments` | 发表评论（workId + content） | 鉴权 |

## 5. 数据与存储

- MySQL `likes` 表：user_id、work_id、created_at（唯一约束防重复）。
- MySQL `comments` 表：work_id、user_id、content、created_at。
- MySQL `works` 表冗余计数：likes_count、comments_count。

## 6. 非功能需求

- **并发**：点赞为高频写操作，需保证计数与关系表一致（事务/条件更新），已纳入 JMeter 压测（混合浏览场景）。
- **性能**：列表接口批量附带点赞状态，避免 N+1 查询。

## 7. 完成状态与后续规划

- **已完成**：点赞 toggle、已赞状态查询、我的喜欢、评论列表与发表、计数联动、未登录浏览放行。
- **待优化**：
  - 评论删除、评论分页与二级回复；
  - 点赞数高并发下引入 Redis 计数再异步落库；
  - 评论内容敏感词过滤/审核；
  - 消息通知（作品被赞、被评论通知作者）。
