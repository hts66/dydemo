# AI 助手模块详细需求

## 1. 模块目标

在私信窗口内提供 AI 助手"小助"：用户用自然语言即可找视频、闲聊。助手基于 **RAG（检索增强生成）** 从视频向量库中召回真实存在的视频，结合大模型生成回复并返回视频卡片；支持多轮记忆、否定条件、流式输出，在 AI 服务故障时可降级，保证"听得懂、推得准、不编造"。

## 2. 总体架构

```text
前端私信窗口
   │  POST /api/chat/agent/stream (SSE)
   ▼
Spring Boot ChatController（透传 + 降级兜底）
   │  POST /chat/stream
   ▼
FastAPI Agent（LangGraph create_react_agent，ReAct 模式）
   ├── 系统提示词（人设 + 工具使用规则）
   ├── 工具① recommend_videos          RAG 向量推荐（核心）
   ├── 工具② search_videos_by_keyword  关键词搜索（调后端 /api/works）
   ├── 工具③ get_hot_videos            热门视频（调后端 /api/works/hot）
   ├── MemorySaver 会话记忆（thread_id）
   └── 输出协议：回复末尾 [VIDEOS]id,id[/VIDEOS]
                 → 后端补全视频卡片 → 前端渲染
```

- Agent 技术栈：Python 3.12、FastAPI、LangGraph、langchain-openai（DeepSeek 兼容 OpenAI 协议）。
- 服务端口 8000，健康检查 `/health`。

## 3. 核心功能需求

### 3.1 对话与工具调用（ReAct）

Agent 对每轮输入先判断意图：

| 用户意图 | 行为 |
| --- | --- |
| 闲聊/身份问题 | 直接按人设回复，不调工具 |
| "推荐/找几个 XX 视频" | 调 `recommend_videos`（RAG） |
| "搜索 XX" | 调 `search_videos_by_keyword`（MySQL LIKE） |
| "热门/有什么好看的" | 调 `get_hot_videos` |
| "换一批/还有吗" | 携带 exclude_ids 重新推荐 |
| "就刚才那个/发给我" | 从上下文取视频 ID，直接输出 [VIDEOS]，不调工具 |
| "按我的喜好推荐" | 分析历史推荐标签，精选 1 个，不调工具 |

### 3.2 系统提示词要点

定义助手人设（活泼简洁，2-4 句话）、四个能力、多轮规则（换一批去重、偏好分析、引用具体视频）、否定条件映射、输出协议（[VIDEOS] 必须在最后一行、只用工具返回的真实数据、found=false 时如实告知）。

### 3.3 RAG 入库管线：视频向量如何生成

入口为后端 `VideoVectorController`（手动批量/单条触发，4 线程并发，每 20 条批量写 Qdrant）：

```text
作品(标题 + 描述 + 封面URL)
   │
   ├─ 有封面 → 下载封面 → Base64 → 通义 qwen-vl-plus 视觉分析（失败重试 2 次）
   │             → 返回 JSON 标签数组 → 仅保留标签库(TagVocabulary)内词汇
   │             → 视觉为空时用标题/描述关键词兜底
   └─ 无封面/视觉失败 → DeepSeek 文本分析（标题+描述推断标签）→ 再失败走字符串匹配
   │
   ├─ 构造 embedding 文本 = 标题 + 描述 + 标签（空则"视频"）
   └─ 通义 text-embedding-v3 生成 1024 维向量 → upsert Qdrant
```

- Qdrant collection：`video_embeddings`，**1024 维**，距离度量 **Cosine**。
- 点 payload：`title、description、tags、source(vision/text)、work_id、user_id`，point ID = work_id。
- 标签体系：三大类（美女/小猫/风景）+ 子类（穿搭、发型、丝袜、猫品种、风景类型等）。
- 历史演进：v1 为 128 维 one-hot 标签向量（`video_tags`），已通过迁移脚本升级为 1024 维语义向量，以支持同义/模糊表达。

### 3.4 RAG 查询流程

```text
用户 query
  → embed(query) 生成查询向量
  → Qdrant 召回 max(limit*4, 20) 条候选（可带 must_not 标签过滤）
  → 排除本会话已推荐 ID（exclude_ids）
  → 候选多于 limit 时随机采样（增加多样性，不按分数排序）
  → 工具返回 JSON 给 LLM 组织回复（末尾附 [VIDEOS]）
  → Agent 解析 ID → 调后端 GET /api/works/{id} 补全卡片(最多5个)
  → SSE 推送给前端
```

### 3.5 否定条件支持（重要）

- 背景：embedding 对否定词不敏感，"没戴眼镜的美女"与"戴眼镜的美女"向量几乎相同，纯向量召回会反向优先命中被否定内容。
- 方案：`recommend_videos` 新增 **`exclude_tags`** 参数，转为 Qdrant **`must_not`** 过滤器在检索阶段硬排除；Python 侧对 payload.tags 再做一层兜底过滤。
- 提示词约定常见映射："没戴眼镜"→`眼镜妹`、"不要黑丝"→`黑丝`、"不要跳舞"→`单人舞,多人舞`、"不要室外"→`室外`；支持组合与"换一批"时保持排除条件。
- 无结果时明确告知"没有找到排除某标签的视频"，不允许凑数。

### 3.6 多轮记忆

- LangGraph **MemorySaver**（进程内存 checkpointer）+ **thread_id**：
  - 首次对话生成 uuid 并通过 SSE `meta` 返回，前端保存并在后续请求携带；
  - 按 thread_id 恢复完整消息历史（含工具调用与结果）参与推理；
  - "重置会话"通过下发新 thread_id 实现等效失忆。
- 记忆用途：已推荐 ID 去重、标签偏好分析、上文视频引用。
- 已知局限：**服务重启记忆丢失**、仅单实例、无跨会话长期画像、长会话 token 膨胀。

### 3.7 流式输出与协议

- SSE 事件：`meta`(thread_id) → `status`(工具执行中 searching) → 多个 `token`(逐字) → `videos`(卡片) → `done` / `error`。
- 流式过程中用过滤器拦截 `[VIDEOS]...[/VIDEOS]` 内部标记，防止泄漏到聊天气泡。
- 后端透传 SSE（120 秒超时），前端打字机渲染，降低首字延迟。

### 3.8 降级策略

Agent 不可达/返回异常时，后端自动降级：关键词意图识别（"推荐/找个/想看" × "视频/作品/内容"）命中则走本地 `VideoRecommendService`，否则走 DeepSeek 纯对话，功能不中断。

## 4. 召回率与精准度

**指标定义**：Recall@K（相关视频被召回的比例）、Precision@K（前 K 条中相关的比例）、MRR/NDCG（排序质量）。当前**尚无评测集，指标未量化**。

**现行策略**：多取候选（20 条）→ 去重 → 随机采样；标签白名单抑制模型编造；否定标签硬过滤。

**问题与提升手段**：

| 问题 | 手段 |
| --- | --- |
| 相似度阈值只写在工具说明里、未代码强制 | 落地 `score >= 0.3` 硬过滤（P0） |
| 标签覆盖窄、口语表达多样 | 查询改写/同义词扩展、扩充标签体系 |
| 无重排 | 引入 rerank（如 bge-reranker）对 top20 重排 |
| 单路向量召回 | 向量 + 关键词 + 标签过滤的混合检索（RRF 融合） |
| 无量化评估 | 构建 query→期望集评测集，离线跑 Recall@20 / Precision@5 / MRR |

## 5. 如何提高 AI 的"智商"

1. **数据层**：入库增加 ASR 语音转写、OCR 字幕、多帧视觉分析（当前仅封面单帧），丰富 embedding 文本。
2. **检索层**：查询改写、混合检索、rerank 重排。
3. **记忆层**：用户画像（观看/点赞/完播聚合为偏好标签或向量），冷启动注入；checkpointer 持久化到 Redis/PostgreSQL。
4. **Prompt 层**：few-shot 示例、输出自检、格式校验重试。
5. **模型层**：复杂组合意图用推理型模型，标签提取任务用低温(0.1)。
6. **工具层**：增加观看历史查询、相似视频、实时热榜；接入 MCP 扩展外部能力。
7. **闭环**：用户负反馈（不感兴趣）埋点回流 + badcase 周分析 + 评测集回归。

## 6. MCP 接口现状与规划

- **现状：无 MCP**。三个工具是进程内 LangChain `@tool` 函数，仅本 Agent 使用。
- 规划：
  - 对外：把推荐/搜索/热门封装为 **MCP Server**（Python MCP SDK，stdio/SSE），供 Trae/Claude 等客户端复用平台检索能力；
  - 对内：Agent 作为 MCP Client 挂载外部只读工具（百科、天气等），扩展通用能力；
  - 约束：工具只读、白名单化，防提示注入扩大攻击面。

## 10. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 提示注入（伪造视频 ID、套取提示词） | 输出 ID 白名单校验、输入消毒、系统提示词保护 |
| LLM 幻觉（编造视频） | 仅允许工具数据 + 卡片回填校验存在性 |
| 记忆易失（进程内存） | Redis/Postgres 持久化 checkpointer |
| 外部大模型限流/故障/成本 | 重试退避、降级链路、embedding 缓存、用量监控 |
| 单点与扩展（单实例/SSE 线程池） | 多实例 + 共享存储、连接数与超时治理 |
| 密钥泄露 | .env 注入、清理历史硬编码密钥并轮换 |
| 内容合规 | 标签体系合规评审、生成内容安全过滤 |
| Agent CORS 过宽（`*`） | 收紧为前端域名白名单 |
