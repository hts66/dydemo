# 社交与私信模块详细需求

## 1. 模块目标

建立用户之间的关系链（关注、粉丝、好友）并提供实时私信能力：消息实时推送、离线不丢、重连可补、未读可见；同时为 AI 机器人会话提供消息落库通道。

## 2. 关注关系需求

- **关注/取关**：同一接口 toggle，返回当前是否关注（Boolean）；不能关注自己。
- **关注状态查询**：进入他人主页时展示"关注/已关注"。
- **关注列表/粉丝列表**：查看任意用户的关注与粉丝。
- **好友关系**：双向关注即互为好友，好友列表用于好友流与私信对象。
- 用户冗余字段维护：following_count、followers_count。
- 防越权：涉及"我的"关系链的查询，userId 只取自 token。

### 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/follows/{followeeId}` | 关注/取关 toggle |
| GET | `/api/follows/{followeeId}` | 是否已关注 |
| GET | `/api/follows/list/{userId}` | 关注/粉丝列表 |
| GET | `/api/follows/friends/{userId}` | 好友（互关）列表 |

存储：MySQL `follows` 表（follower_id、followee_id、created_at），用户表冗余计数。

## 3. 实时私信需求（WebSocket）

### 3.1 连接

- 端点：`/api/ws/chat`。
- 鉴权：浏览器 WS 无法自定义请求头，JWT 通过 **query 参数**传递，由 `WebSocketAuthInterceptor` 校验。
- 后端用 `ChatSessionRegistry` 维护在线用户连接（userId → session）。

### 3.2 消息收发

- 发送方 HTTP 发消息落库：`POST /api/messages`（receiverId、content）。
- 接收方**在线**：服务端通过其 WebSocket 连接实时推送，前端无需轮询。
- 接收方**离线**：不在线时记录离线场景日志；消息已在 HTTP 发送时落库，等其打开会话时通过 HTTP 拉取。

### 3.3 会话与拉取

- 拉取与某用户的历史消息：`GET /api/messages/chat/{otherUserId}`（按时间排序）。
- **打开聊天窗口即拉取**，作为离线消息补偿机制。
- 仅当前登录用户可访问自己的会话。

### 3.4 连接可靠性（前端 `utils/ws.js`）

- 心跳：每 **30 秒**发送心跳保活；
- 断线自动重连：**3 秒**后重连；
- **重连成功后自动拉取消息**，补齐断线期间的漏收消息；
- 连接状态对 UI 可见：聊天窗口头部展示绿点（已连接）/灰点（重连中）。

### 3.5 未读消息

- 新消息仅在对应聊天窗口未激活时插入会话列表并累计未读；
- 好友弹窗与聊天侧边栏展示未读红点角标，超过 99 显示 **99+**；
- 打开对应聊天窗口时未读数清零。

## 4. AI 机器人会话

- AI 助手作为特殊会话对象出现在消息列表。
- 前端与 AI 的对话消息通过 `POST /api/messages/bot` 落库，使 AI 聊天与普通私信共用一套会话 UI 与历史记录。
- AI 的生成逻辑见《05-AI助手模块》。

## 5. 业务规则

- 只有登录用户可建立 WS 连接、发私信、查看自己的会话。
- 实时推送只推给在线接收者；离线消息依赖打开会话时的 HTTP 拉取，不做额外推送通道。
- 消息发送触发频控时，发送按钮临时禁用并给出视觉反馈。

## 6. 完成状态与后续规划

- **已完成**：关注/粉丝/好友、WebSocket 鉴权连接、在线实时推送、离线拉取补偿、30s 心跳、3s 重连、未读 99+ 角标、连接状态指示、AI 机器人消息落库。
- **待优化**：
  - 会话列表分页与总未读数接口（当前以前端聚合为主）；
  - 消息已读回执、输入中状态；
  - 图片/表情等富媒体消息；
  - WS 集群化（多实例下用 Redis Pub/Sub 跨节点投递）；
  - 离线推送（Web Push / 移动端通知）。
