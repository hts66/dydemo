# 用户模块详细需求

## 1. 模块目标

提供完整的账号体系：用户可通过邮箱完成注册、登录（密码/验证码两种方式）、找回密码；登录后维护个人资料；系统通过 JWT 识别用户身份，保护需要登录的操作，同时放行公开内容浏览。

## 2. 功能需求

### 2.1 图形验证码

- 进入登录/注册/找回密码页面时获取图形验证码。
- 后端使用 Java 原生 `java.awt` 生成：4 个随机字符 + 10 条干扰线 + 20 个彩色噪点，返回 Base64 图片和验证码 ID（UUID）。
- 验证码答案存 Redis，key 为 UUID，**有效期 5 分钟**，一次性使用，验证后删除。
- 所有登录、注册、发送邮箱验证码类操作都必须先校验图形验证码。

### 2.2 邮箱验证码

- 通过 QQ 邮箱 SMTP 发送 6 位数字验证码。
- 存储：Redis，key 格式 `email_code:{email}`，**有效期 5 分钟**。
- 发送频率限制（倒计时），防止滥用；触发限流时发送按钮临时禁用并给出视觉反馈。

### 2.3 注册

- 字段：邮箱、用户名、密码（BCrypt 加密入库）。
- 校验：邮箱格式、邮箱未被注册、图形验证码正确、邮箱验证码正确。
- 支持两种入口：常规注册（`/api/auth/register`）与带验证码的直接注册登录（`/api/auth/register/code`，注册成功直接签发令牌）。

### 2.4 登录

- **密码登录**：邮箱 + 密码 + 图形验证码；BCrypt `matches()` 比对。
- **验证码登录**：邮箱 + 邮箱验证码 + 图形验证码，无需密码。
- 登录成功返回 Access Token、Refresh Token 与用户信息。

### 2.5 令牌机制

- Access Token：有效期 **30 分钟**；Refresh Token：有效期 **7 天**。
- 前端将令牌存 localStorage，请求头携带；拦截器在 401/令牌过期时用 Refresh Token 静默换新，失败则弹出会话过期弹窗引导重新登录。
- 刷新接口：`POST /api/auth/refresh`。

### 2.6 找回/重置密码

- 通过邮箱验证码校验身份后重置密码（`/api/auth/forgot-password` 发码 → `/api/auth/reset-password` 重置）。
- 新密码重新 BCrypt 加密存储。

### 2.7 个人资料

- 可修改：用户名、性别、简介、头像、个人主页背景图。
- 头像/背景先经上传接口得到 URL，再更新用户资料；也支持直接上传文件的接口。
- 查看任意用户公开资料：`GET /api/users/{id}`。
- 个人主页展示：头像、昵称、简介、背景、作品数、关注数、粉丝数、获赞数。

## 3. 业务规则

- 密码不落明文，统一 BCrypt；验证码一次性、5 分钟过期。
- 未登录可浏览公开内容（视频、作品、点赞数等）；发布、点赞、评论、关注、私信等写操作必须登录。
- 用户只能修改自己的资料。
- 业务错误 HTTP 状态码必须非 200，前端拦截器据此弹错。

## 4. 接口清单

| 方法 | 路径 | 说明 | 是否放行 |
| --- | --- | --- | --- |
| GET | `/api/captcha` | 获取图形验证码（Base64 + captchaId） | 放行 |
| POST | `/api/auth/send-code` | 发送邮箱验证码（先验图形验证码） | 放行 |
| POST | `/api/auth/verify-code` | 校验邮箱验证码 | 放行 |
| POST | `/api/auth/register` | 邮箱密码注册 | 放行 |
| POST | `/api/auth/register/code` | 验证码注册并登录 | 放行 |
| POST | `/api/auth/login` | 密码登录 | 放行 |
| POST | `/api/auth/login/code` | 验证码登录 | 放行 |
| POST | `/api/auth/forgot-password` | 找回密码（发码） | 放行 |
| POST | `/api/auth/reset-password` | 重置密码 | 放行 |
| POST | `/api/auth/refresh` | 刷新令牌 | 放行 |
| GET | `/api/users/{id}` | 查看用户公开资料 | 放行 |
| PUT | `/api/auth/user/profile` | 修改个人资料 | 鉴权 |
| PUT | `/api/auth/user/avatar` | 更新头像 | 鉴权 |
| PUT | `/api/auth/user/background` | 更新背景图（文件） | 鉴权 |
| PUT | `/api/users/background` | 更新背景图（URL） | 鉴权 |

## 5. 数据与存储

- MySQL `users` 表：账号、密码哈希、头像、背景、性别、简介、关注/粉丝/获赞统计。
- Redis：图形验证码、邮箱验证码。
- MinIO：头像、背景图文件。

## 6. 完成状态与后续规划

- **已完成**：上述全部功能，含双令牌刷新、会话过期弹窗、发送验证码倒计时。
- **待优化**：
  - 登录失败次数限制与账号锁定；
  - Refresh Token 服务端黑名单/轮换机制；
  - 邮箱验证码发送的更强频控（IP 维度）；
  - 用户注销账号功能。
